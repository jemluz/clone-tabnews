### Defining a node version for your project

When we talk about **node.js** projects, one of the problems we're sure to face is `versioning`.

That's why from the start of the project we have to make it clear which version of node is compatible/recommended for your development.

**nvm (Node Version Manager)** is a tool that allows us to handle different versions of node on our machine with ease.

Let's use it in the terminal to run `nvm install lts/hydrogen` and use that version in our development environment. And then use `nvm alias default lst/hydrogen` to set this version as the default.

{/* ![](/img/dia-03/index/04.png) */}

This way the **node version has been standardized for my local environment.**

But we still need to standardize so that other devs who may access the repository know which version is ideal...

### Configuring.nvmrc

To do this, we'll use `.nvmrc`, a file that stays inside our project and keeps the **information about which version of node should be used.**

{/* ![](/img/dia-03/index/05.png) */}

The file should **only** contain **one line with the desired node version**.

When you run `nvm install` or `nvm use` in the terminal, it will search for `.nvmrc` and install the version of the file, if there is one.

{/* ![](/img/dia-03/index/06.png) */}

{/* ![](/img/dia-03/index/07.png) */}

#### Suffix rc = Run Commands

This suffix is traditionally used in **configuration files** to indicate that they contain settings or commands that **should be run or read by a specific program.**

- `.nvmrc` → will be read by **nvm**
- `.bashrc` → will be read by **bash**
- `.npmrc` → will be read by **npm**
