### Definindo uma versão node para o seu projeto

Quando falamos em projetos com **node.js** um dos problemas que certamente iremos enfrentar são sobre `versões`.

Por isso desde o inicio do projeto temos que deixar claro qual versão do node é compatível/recomendada para seu desenvolvimento.

O **nvm (Node Version Manager)** é uma ferramenta que permite lidarmos com diferentes versões do node na nossa maquina com facilidade.

Queremos o **node versão** **lts/hydrogen**

{/* ![](/img/dia-03/index/04.png) */}

Vamos utilizar ele no terminal para rodar o `nvm install lts/hydrogen` e usar essa versão no nosso ambiente de desenvolvimento. E em seguida usar o `nvm alias default lst/hydrogen` para definir essa versão como padrão.

{/* ![](/img/dia-03/index/05.png) */}

{/* ![](/img/dia-03/index/06.png) */}

{/* ![](/img/dia-03/index/07.png) */}

Dessa forma a **versão do node foi padronizada para o meu ambiente local.**

Mas ainda precisamos padronizar para que outros devs que eventualmente acessem o repositório saibam qual a versão ideal…

### Configurando o .nvmrc

Para isso iremos utilizar o `.nvmrc`, um arquivo que fica dentro do nosso projeto mantendo a **informação de qual versão do node deve ser utilizada.**

{/* ![](/img/dia-03/index/08.png) */}

O arquivo deve conter **apenas uma linha com a versão do node desejada**.

Ao rodar `nvm install` ou `nvm use` no terminal ele irá buscar pelo `.nvmrc`, e instalar a versão do arquivo, se houver um.

{/* ![](/img/dia-03/index/09.png) */}

{/* ![](/img/dia-03/index/10.png) */}

#### Sufixo rc = Run Commands

Este sufixo é tradicionalmente usado em **arquivos de configuração** para indicar que eles contêm configurações ou comandos que **devem ser executados ou lidos por um programa específico**.

- `.nvmrc` → será lido pelo **nvm**
- `.bashrc` → será lido pelo **bash**
- `.npmrc` → será lido pelo **npm**
